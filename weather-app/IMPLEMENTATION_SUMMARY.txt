Key Features:
  ✓ Lazy-loads sentence-transformers model (cached)
  ✓ Embeds query text using same model (384-dim)
  ✓ Cosine similarity search via pgvector <=> operator
  ✓ Returns top_k results (1-20, default 5)
  ✓ Joins embeddings with documents for full metadata
  ✓ Handles empty table gracefully

Query Implementation:
  SELECT d.id, d.location, d.headline, e.chunk_text,
         1 - (e.embedding <=> '[...]'::vector) AS similarity
  FROM weather_embeddings e
  JOIN weather_documents d ON d.id = e.document_id
  ORDER BY e.embedding <=> '[...]'::vector
  LIMIT ?

Data Flow:
  1. NWS API → weather_client.py → weather_documents (raw text)
  2. weather_documents → ingest_weather_embeddings.py → weather_embeddings (vectors)
  3. User query → app.py (/weather/search) → pgvector search → results

Technology Stack:
  • Data Source:    NWS API (api.weather.gov) - public, no auth required
  • Database:       Lakebase Postgres + pgvector extension
  • Embeddings:     sentence-transformers/all-MiniLM-L6-v2 (384-dim)
  • Vector Index:   HNSW with cosine distance
  • API:            Flask REST
  • Write Path:     psycopg2 (NOT Spark, per requirements)

Vector Search:
  • Operator:       <=> (cosine distance)
  • Similarity:     1 - distance (0-1 scale, higher = more similar)
  • Index:          HNSW(embedding vector_cosine_ops)
  • Parameters:     m=16, ef_construction=64

Key Design Decisions:
  1. Same embedding model as ticker-news app (384-dim) for consistency
  2. Chunking with sliding window to preserve context across boundaries
  3. psycopg2 for writes (Spark JDBC not supported for Lakebase)
  4. HNSW index for sub-linear search time (better than IVFFlat for small datasets)
  5. Separate documents + embeddings tables for flexible schema evolution

To deploy and test:

  1. Initialize database:
     psql <lakebase-url> < sql/setup_weather_embeddings.sql

  2. Sync weather data:
     curl -X POST http://localhost:8080/weather/sync \
       -d '{"locations": [...], "limit": 50}'

  3. Generate embeddings:
     python notebooks/ingest_weather_embeddings.py

  4. Test search:
     curl -X POST http://localhost:8080/weather/search \
       -d '{"query": "severe thunderstorms", "top_k": 5}'
